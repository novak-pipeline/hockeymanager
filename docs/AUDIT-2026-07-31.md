# UI audit — 2026-07-31

A sweep of every screen for **dead controls, raw numbers, self-contradicting
text, broken-looking empty states and unfinished corners**, prompted by two bugs
in `docs/PLAYTEST-2026-07-31.md` that shared a cause: *nothing in the automated
stack has ever clicked anything.*

Both were invisible to a clean typecheck **and** 2264 passing tests:

- every sidebar destination silently rendered the dashboard (`AnimatePresence`
  exit deadlock, fixed in d422fb2);
- the Roster **View:** dropdown was unclickable, hiding two whole column sets (G1).

The premise of this audit was that if two shipped, more have. That premise held.

---

## The hole, and how it is now closed

`scripts/dev/ui-snapshot.mjs` drove the game with **Continue** and photographed
the result. A screenshot of the dashboard taken while standing on *Tactics* is
byte-identical to a screenshot of the dashboard — which is exactly why the nav
ship-blocker survived a full snapshot run.

New: **`scripts/dev/ui-audit.mjs`**, wired into the harness, making three
assertions a screenshot cannot.

| Assertion | What it catches | Why the old harness missed it |
|---|---|---|
| **NAV** — after clicking a destination the *main pane's* content must change, and must not equal the dashboard's | the AnimatePresence deadlock, in the exact shape it shipped | it asserted nothing; and asserting on the nav highlight is worthless — during the deadlock the highlight moved **correctly** |
| **HIT-TEST** — every visible control must be the topmost element at its own centre point | occluding overlays, flex-collapsed zero-size boxes, `pointer-events:none` | none of these are visible in a screenshot |
| **EXERCISE** — tabs, sub-tabs, sortable headers and dropdowns are operated, and the pane fingerprinted before/after | inert controls | nothing was ever operated |

Notes on the implementation worth keeping:

- The nav walk reads the rail **from the DOM**, not from a hardcoded list, so a
  destination added to `navConfig.ts` is audited the day it lands.
- The fingerprint folds in `<select>`/`<input>` **values** and which elements
  carry `.active`. Text alone is not enough: a `<select>`'s `innerText` is every
  option's label whether or not it is the chosen one, so a text-only fingerprint
  reported every *working* dropdown as inert. That cost a full round of false
  positives on the Dev Centre before it was noticed.
- Only **non-destructive** controls are exercised (a label denylist covers
  Continue / Accept / Sign / Trade / …), so the audit can run against a live
  career without changing it.
- A **DEAD** finding sets a non-zero exit code. This is the gate the nav bug
  walked through; it should not be a log nobody opens.
- **Coverage is reported alongside findings** (destinations opened / controls
  hit-tested / controls operated), and a run that operated *nothing* fails rather
  than reporting clean. "0 findings" and "0 controls examined" otherwise print the
  same reassuring line, and a silently-vacuous audit is worse than no audit — it
  is the same false comfort a green suite gave the nav bug.

Run it:

```bash
npm run ui:audit
```

That is the fast gate — it stops after the shell loads instead of walking a
season, so it costs minutes, and should be run on any UI change. The full
`npm run ui:snap` now also does a second control pass per screen with a
**mid-season** state behind it, since a control that only appears once there are
standings and stats to switch between is not reachable in the offseason pass.

**First run, against the built app (seed 424242): 22 destinations, 0 DEAD, 19
other findings.** The nav fix is genuinely holding — every destination renders
its own distinct content and no pane held more than one screen wrapper — so the
19 were control-level, and triaging them is what produced the list below (four
turned out to be harness false positives, each now fixed at the source: the
select fingerprint, already-active tabs, transient toasts, and closed
`<details>`).

**Run after the fixes: 22 destinations, 328 controls hit-tested, 20 operated, 0
findings.** The coverage numbers are the point — they are what make that zero
mean something.

## Findings — fixed inline

Ranked by how badly each misleads the GM.

### 1. Roster **View:** dropdown was inert — and so is every other native `<select>` in the app *(playtest G1)*

**Root cause, and it is not local to the Roster screen.** A native `<select>`
opens an OS-level popup that Chromium tears down when the element re-renders.
Every screen re-renders on the global refresh bus (`useScreenData`), so on a busy
day the popup closes in the frame it opened — the control reads as simply not
responding. The trade centre had already hit this and grown its own custom
partner dropdown, with a comment saying so
([TradesScreen.tsx](src/renderer/screens/TradesScreen.tsx)); nobody generalised it.

Fixed by extracting that pattern into
[Dropdown.tsx](src/renderer/components/Dropdown.tsx) — an in-DOM listbox that
survives re-renders — and putting the Roster switcher on it.

**Verified against the running app**, not inferred:
[verify-roster-view.mjs](scripts/dev/verify-roster-view.mjs) (`npm run
ui:verify-roster-view`) drives the real Electron build, opens the dropdown, picks
*Contract* and asserts Salary/Years/Expires/Clauses appear, picks *Statistics*
and asserts GP appears, then switches back. It passes. The general audit's
"operating this changed the screen" would also have passed on a dropdown that
merely opened; this one names the payoff the bug denied.

Note the audit's exercise list now includes `.dropdown > button.select`
alongside `select` — otherwise each migration off a native `<select>` would
quietly delete its own test coverage.

> ⚠️ **13 native `<select>`s remain** and carry the same latent defect. See
> "reported, not fixed" #A below.

### 2. The player profile quoted a salary cap the league stopped using years ago

[PlayerProfileScreen.tsx](src/renderer/screens/PlayerProfileScreen.tsx) hardcoded
`83_500_000` — for both the "of $83.5M cap" text **and the meter's width**. Cap
growth has been in since the NHL-realism pass, so by 2032 the panel confidently
quoted a stale ceiling and drew a bar that was wrong with it.

Fixed by threading the live league ceiling through: `ViewCtx.salaryCap` (optional,
so older ctx builders and tests keep compiling) → `ProfileContractView.salaryCap`
→ the panel. The literal survives only as a fallback for a ctx that supplies none.

### 3. The Roster's own column headers contradicted its cells

The header tooltips read *"Overall ability (0–100)"*, *"Condition / fitness
(0–100)"*, *"Morale (0–100)"* — over cells that render **a star rating, a bar and
a mood word**. The house rule ("never surface the raw overall — only stars") was
being kept in the cells and broken in the tooltip that explains them. Reworded to
describe what is actually shown.

### 4. A sort that shipped unreachable

`SquadScreen`'s `SortKey` union included `'years'` and `sortRows()` had a working
`case 'years'` — but the **Years** header was a plain `<th>`. The sort existed,
was typed, was correct, and no control reached it; meanwhile the column sat as an
inert click target between five sortable neighbours. Wired to `SortTh`.

### 5. Trade-value chip rendered an unrounded float

`PlayerChip` in [TradesScreen.tsx](src/renderer/screens/TradesScreen.tsx) rendered
`· {props.value}` and a `Trade value: ${props.value}` tooltip — raw, so a chip
could read `· 22.913478562`. Every other value read on that screen is one
decimal. Rounded to match. *(The deeper objection to the bare decimal is #C.)*

### 6. Roster fit surfaced as `63/100` in four places across three screens

The engine already computes a **word** (`fitLabel`: Strong / Good / Adequate /
Poor) and hands it to some screens — but the Tactics header, the Job Market's
current-coach line, the coach-market table and the staff meeting summary printed
the raw score anyway, and the Tactics/Job-Market ones had no word at all. Added
`rosterFitWord()` to
[format.ts](src/renderer/components/format.ts) mirroring the engine's thresholds;
all four now read the word, with the number kept in the tooltip.

### 7. An entire obsolete navigation rail was still in the tree

`src/renderer/components/Sidebar.tsx` — a complete second sidebar with the old
labels (*Squad*, *Dashboard*, *Trades*, *Match Center*) and its own `NavButton`.
Nothing imported it; `SideNav.tsx` is the real rail. Deleted. It is the kind of
thing that reads as unfinished to anyone opening the folder, and worse, would
have been a plausible place to "fix" a nav bug that lives elsewhere.

### 8. Five bare "No data yet." empty states

`Statistics → Leaders`, `Competitions → Overview`, the Team screen's *Category
bests*, `Scouting → Coverage` and two `Data Hub` tables all rendered a flat *"No
data yet."*. In preseason — when a new GM is most likely to look — that reads as a
broken panel, not an intentional one. Each now says **why** it is empty and what
fills it ("No games have been played yet — leaders fill in once the season is
under way"), matching the voiced style the dashboard already uses ("Nothing here
— a quiet desk").

## Findings — reported, not fixed

Each of these is real and each is too big to do safely inside an audit chip.

### A. 13 native `<select>`s carry the G1 defect *(highest priority of this section)*

`Dropdown.tsx` now exists and is proven on the Roster screen. Remaining sites:

| Screen | Count | What is behind the control |
|---|---|---|
| `PlayerProfileScreen` | 3 | squad status, trade status, "Compare vs" |
| `TacticsScreen` | 2 | system/deployment pickers |
| `MentorshipScreen` | 2 | mentor pairing |
| `DevelopmentScreen` | 1 | **per-prospect practice focus** — one per row |
| `SquadPlannerScreen` | 1 | bulk squad status |
| `ScoutingScreen` | 1 | assignment |
| `NegotiationScreen` | 1 | offer terms |
| `DraftRankingsScreen` | 1 | board filter |
| `DataHubScreen` | 1 | metric picker |
| `App.tsx` | 1 | shell-level |

This is mechanical (swap the element, map `<option>`s to the options array) but
it touches ten screens and each needs its own eyeball, so it wants its own pass.
**`DevelopmentScreen` deserves to go first** — it is the control the GM uses to
steer prospect growth, it appears once per row, and if it does not open the whole
development-focus feature is unreachable.

### B. Staff ability and judgment are bare 0–100 integers in 13 places

`{c.rating}`, `{c.judgment}`, `({s.rating})` across Job Market, Scouting, Scout
Profile, Team, Data Hub, Player Profile and World. Players are protected by the
stars rule; staff are not, and a coach shown as `73` is the same spreadsheet tell
the rule exists to prevent.

**Why this is not a one-liner:** `overallToStars()` is calibrated for NHL player
overalls (88+ = 5★). Staff ratings do not share that distribution, so reusing the
curve would misread them — a competent scout would render as one star. This needs
a staff-specific curve (or word scale) derived from the actual generated
distribution, which is a measurement job, not a rename.

### C. Trade value as a bare decimal — the presentation half of the trade epic

Playtest **A1**. The chips still read `22.9` / `60.7`, and the user has objected
twice. The wanted read is a bar/meter like the EA NHL games, or a tier word.

Deliberately **not** done here: A1 is one face of the epic whose keystone is
**A2 — value is global, not per-club**. Shipping a pretty meter over a single
global number would make a mechanical valuation *look* considered while staying
exactly as mechanical. The meter should land with (or after) per-club valuation,
reading that club's number. Rounding the raw float (#5 above) is the part that
was simply broken.

### D. The dashboard's no-scroll viewport is over-subscribed

The first audit run flagged controls on **Home** covered at their centre point by
`.dash-banner` and `.dash-grid`. Part of that was a harness false positive (a
closed `<details>` still lays out its absolutely-positioned contents — now
skipped), but the shape is worth chasing deliberately: the dashboard laws say
*one screen, no scroll*, and when banner rows stack up (deadline + cut day +
board meeting can all be pending at once) something has to give. Worth a
dedicated pass that drives the dashboard into its **most crowded** state and
hit-tests it, rather than the quiet offseason day this audit happened to see.

### E. Sortability is inconsistent and invisible at rest

In the Roster table six headers sort and the rest do not, and `.sortable` only
differs on **hover** (`cursor: pointer` + a background change). A GM clicking
*Expires* or *Clauses* gets silence with no way to know it was never a button.
Either make every column sortable (several already have view fields that would
support it) or give sortable headers an at-rest affordance. #4 above removed one
instance; the pattern remains.

## What this audit did **not** cover

Said plainly so it is not mistaken for a clean bill of health:

- **The match-day and 3D renderers.** The audit walks the management shell; the
  rink is a canvas and the fingerprint cannot read it.
- **Modal and gated flows** — the draft floor, the negotiation room, board and
  staff meetings, training camp week. They are reachable only by advancing the
  career, and the audit deliberately refuses to press anything that advances it.
  The full `ui:snap` walk photographs them; nothing clicks their controls yet.
  This is the obvious next extension: a destructive-allowed audit mode running
  against a throwaway save.
- **Anything requiring judgement about the numbers themselves** — whether a value
  is *right*, only whether it is *shown like a spreadsheet*.
