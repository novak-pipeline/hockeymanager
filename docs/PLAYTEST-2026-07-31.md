| # | Finding | Severity |

### H1–H3 — CLOSED 2026-07-31 (2 critical + 4 major → 0 + 0 on the same seed)

Three separate holes, one theme: an offer was treated as valid because it hadn't
expired yet, and the GM's own deals were the one trade path nobody policed.

- **H1 — validity ≠ expiry.** `offerDeadReason()` asks whether every asset an
  offer names is still where it was (your man on your NHL roster, their man on
  theirs, both picks still owned); `pruneDeadOffers()` retires the ones that
  aren't, with a call from the GM who tabled it ("PIT pull their offer — Sidney
  Crosby is no longer on your NHL roster") so the desk clearing itself reads as
  news. It runs on every advance and before every read of the offer list.
- **H2 — a deal you can't complete is not an offer.** Both generators checked
  only the PARTNER's cap; they now check the user's the same way, so the illegal
  offer is never tabled. Room can still vanish after it's tabled, so
  `TradeOfferView.blockedReason` carries the reason, both screens grey out Accept
  and print it, and the AGM's read (`assessTrade`) now runs the identical
  arithmetic — he can't bless a deal the engine will refuse.
- **H3 — the remaining uncapped path was `executeUserTrade`.** Every INCOMING
  offer was cap-guarded; the trades the GM proposed himself went propose → sleep
  on it → execute with no cap check at all. That is what put a club $6.5M over
  the ceiling with Gap #4's `callUp` guard already in place. Now the deal falls
  through and says why (the caller already reported that as news), and
  `proposeTrade` refuses up front rather than two days later. The emergency
  recall pass is untouched — it still eats an overage to ice a legal lineup, as
  `callUpCap.test.ts` pins.
- **And a fourth, found by the fix.** With H1/H2 closed the autopilot surfaced
  one more throw: two clubs bidding for the same player, one deal taken, the
  other offer accepted off a stale list. `acceptTrade` no longer throws on that —
  it returns `{ ok, message }` (the worker still raises it to the UI as an error
  banner, exactly as `resignPlayer` does), because an offer going dead under you
  is an ordinary race, not an invariant violation.
